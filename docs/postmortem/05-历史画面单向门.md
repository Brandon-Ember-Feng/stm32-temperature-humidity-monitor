# 复盘 05 · 历史画面进去出不来（单向门）

| 项 | 内容 |
|---|---|
| 发生时间 | 2026-09（v1.2 开发期） |
| 影响范围 | 用户被困在历史画面，只能按复位键 |
| 严重度 | 中（可恢复，但体验上等于功能做死） |
| 类别 | 交互设计缺陷（不是代码 bug） |

---

## 现象

历史画面（画面 3）为了能"一页页往后翻"，把**短按**占用为翻页：

```
短按 K1 → 历史画面内：翻到下一页
短按 K1 → 其他画面：切到下一个画面
```

结果：用户短按进入历史画面后，**再怎么按都只是在历史页之间循环，永远回不到其他画面**。

唯一的出路是**按复位键**（会丢失运行时间、并重新走一遍上电自检）。

---

## 定位过程

### 第 1 步：这不是"代码写错了"，而是"设计没考虑出口"

先核对代码逻辑 —— 它是**完全正确的**：

```c
if (g_mode == 3U)          /* 历史画面：按键用来翻页 */
{
    g_hist_page++;
    if (g_hist_page >= pages) g_hist_page = 0U;    /* 翻到末页回到第 1 页 */
    OLED_PageHistory();
}
else                       /* 其他画面：切到下一个画面 */
{
    g_mode++;
    if (g_mode >= MODE_NUM) g_mode = 0U;
}
```

翻页逻辑正确、循环正确、页号复位正确 —— **没有一个 bug**。

问题出在更早的地方：**设计"单按键 + 多画面"这个交互时，没有为每个画面检查"有没有出口"**。

### 第 2 步：把"状态 → 输入 → 转移"列成表，缺口的形状就出来了

| 当前画面 | 短按的语义 | 出口（能去哪个画面） |
|---|---|---|
| 0 温湿度 | 切下一画面 | → 1 ✔ |
| 1 时间 | 切下一画面 | → 2 ✔ |
| 2 极值 | 切下一画面 | → 3 ✔ |
| **3 历史** | **翻页**（不是切画面） | **→ 无 ✔✗** ← **缺口** |
| 4 WiFi | 切下一画面 | → 0 ✔ |

⇒ **画面 3 是一个"汇点"（sink）**：可以进入，没有任何边可以离开。

这是一个纯粹的状态机完整性问题：**存在一个不可达出边的状态，而系统只有一个输入通道（按键）**。

### 第 3 步：确认"只有一个输入"这个前提

系统只有一个按键 K1。没有第二个按键、没有触摸、没有串口命令可以切画面。

⇒ **唯一的按键被翻页占用了，就真的没有任何其他手段能出去。**

（如果当初有第二个按键，这就不是问题 —— 所以根因的形式是"单输入通道 + 输出被占用"，而不是"翻页这个决定错了"。）

---

## 根因

**在"单按键多画面"的设计里，把某个画面的按键语义从"切画面"改成了"页内操作"，却没有为该画面保留另一条离开路径。**

这是一个**设计层面的缺陷**，用"状态机无出边"可以精确描述。它不会让任何一行代码报错，只有真的用起来才会暴露 —— 而且一旦暴露，用户的感觉是"这个功能做坏了"。

---

## 修复与验证

### 修复：引入"长按 = 逃生门"

给按键增加第二个语义：

| 动作 | 行为 | 适用范围 |
|---|---|---|
| 短按 | 切下一画面；在历史画面内为翻页 | 全部画面 |
| **长按 ≥ 1 s** | **直接回到画面 0（温湿度）** | **全部画面，无条件生效** |

关键点：长按的回主画面行为**不判断当前画面**，在哪儿按都有效 —— 这样将来再加任何"吃按键"的画面，出口都已经存在。

```c
uint8_t k = Key_Scan();

if (k == 2U)                    /* ---------- 长按：回主画面 ---------- */
{
    g_mode      = 0U;           /* 回到温湿度画面 */
    g_hist_page = 0U;           /* 页号也复位，下次进历史从头算 */
    OLED_Refresh();
    /* 长按给"双闪"反馈 */
    LED_On(); delay_ms(60U); LED_Off(); delay_ms(80U);
    LED_On(); delay_ms(60U); LED_Off();
}
else if (k == 1U)               /* ---------- 短按 ---------- */
{
    if (g_mode == 3U) { /* 翻页 */ }
    else              { /* 切画面 */ }
    LED_On(); delay_ms(30U); LED_Off();     /* 单闪反馈 */
}
```

### 配套设计：让用户"知道"有长按这回事

只有逃生门还不够 —— 用户得知道它存在。所以：

1. **按键时 LED 给不同反馈**：短按单闪、长按双闪。用户**不用盯着屏幕**就能确认自己那一下被识别成短按还是长按
2. **README 与项目说明书明确写出来**："历史画面需长按才能退出"
3. **串口日志打印**：`[按键] 长按(>=1s) -> 回到画面 1/4（温湿度）`，远程调试时也能看到
4. **故障速查表里列一条**："按键卡在历史画面出不来 → 该画面短按是翻页，需长按 1 秒返回"

### 验证

| 项 | 结果 |
|---|---|
| 在历史画面长按 1 s | 回到画面 0，页号复位 ✔ |
| 在其他画面长按 1 s | 同样回到画面 0（无条件） ✔ |
| 长按过程中 | 不产生短按副作用（不会先翻一页再跳回） ✔ |
| 按键反馈 | 短按单闪、长按双闪，可区分 ✔ |

> "长按过程中不产生短按副作用"这一条依赖于 **按键扫描只在"松手那一刻"上报一次**的设计
> （见 `docs/design/03-详细设计.md` §2.7.2）。
> 如果按下就先报一次短按、按住 1 秒后再报一次长按，用户会看到"先翻了一页、又突然跳回主画面"。

---

## 可迁移的教训

1. **每个"能进入的状态"都必须先问"怎么出去"。**
   这条规则对 UI 画面、协议状态机、错误分支同样适用。
   在评审时用一句话就能测出来："如果我现在卡在这里，我怎么回到正常状态？"
2. **单输入通道的系统里，任何"占用输入"的设计都要同时给出替代入口。**
   单按键、单串口、单中断源都有这个问题。
3. **这类缺陷不会被编译器和单元测试发现**，因为它不违反任何语法或逻辑规则。
   它只能靠**把交互穷举成状态转移表**来发现 —— 表格里出现"无出边"的格子，就是缺口。
4. **逃生门必须"无条件生效"**，不要写成"仅当在画面 3 时"。
   条件是将来最容易被改坏的地方；无条件的设计在新增画面时天然仍然成立。
5. **给了逃生门，还要让用户找得到它**：视觉/听觉反馈 + 文档 + 故障速查，三处都要写。
   一个用户不知道存在的功能，等于不存在。
