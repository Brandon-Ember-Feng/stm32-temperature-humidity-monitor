# 复盘 02 · W25Q64 读回 0x000000 / 0xFFFFFF

| 项 | 内容 |
|---|---|
| 发生时间 | 2026-09（v1.2 开发期） |
| 影响范围 | 历史记录功能完全不可用 |
| 严重度 | 中（有降级路径，不影响主功能） |
| 定位耗时 | 约 40 分钟 |
| 类别 | 接线 / 总线配置 |

---

## 现象

上电自检输出：

```
[W25Q64] JEDEC ID = 0x000000
[W25Q64] 识别失败！请检查接线：
           CS->PA4  CLK->PA5  DO->PA6(MISO)  DI->PA7(MOSI)
           VCC 必须是 3.3V（W25Q64 不耐 5V）
```

正常情况下应该读到 `0xEF4017`（`0xEF` = 华邦，`0x40` = SPI Flash 系列，`0x17` = 8 MB）。

**关键特征：读到的不是随机值，而是全 0。**

---

## 定位过程

### 第 1 步：先用"读到什么"缩小范围

这类总线故障，读回的**具体数值**本身就是诊断信息：

| 读回值 | 指向 | 原因 |
|---|---|---|
| `0x000000` | MISO 恒为 0 | MISO 被拉低（接错/短路）或从机根本没驱动这条线 |
| `0xFFFFFF` | MISO 恒为 1 | MISO 悬空（上拉/浮空输入读到高），即**从机的输出没接上来** |
| 随机值 | 时序/模式问题 | SPI 模式不匹配、时钟过快 |

我们读到 `0x000000` ⇒ **MISO 是恒低**，不是悬空。

### 第 2 步：区分"接线错"与"芯片错"

先做成本最低的排查：**用万用表/目测核对四根线**。

STM32 侧的配置是：

```
PA4  CS    推挽输出（软件片选，低电平选中）
PA5  CLK   复用推挽
PA6  MISO  浮空输入
PA7  MOSI  复用推挽
```

肉眼核对后发现：模块侧丝印是 `VCC GND CS CLK DO DI`，而 **DO 接在了 PA7，DI 接在了 PA6**。

### 第 3 步：为什么"接反"会表现成恒低

| 模块丝印 | 含义 | 方向 | 应接 |
|---|---|---|---|
| `DO` | Data Out（Flash 的输出） | 出 | STM32 的 MISO = `PA6` |
| `DI` | Data In（Flash 的输入） | 入 | STM32 的 MOSI = `PA7` |

接反之后：
- STM32 的 `PA6`（浮空输入，期待从机驱动）实际连到了模块的 **DI（输入脚）** ⇒ 无人驱动 ⇒ 读到低
- STM32 的 `PA7`（推挽输出，发命令）实际连到了模块的 **DO（输出脚）** ⇒ **两个输出脚对驱**

⇒ 从机完全没收到命令，主机也收不到任何数据，`PA6` 呈现的是被模块输入脚拉住的低电平 ⇒ `0x000000`。

> 顺带一个隐患：`PA7`（推挽输出）与模块 `DO`（输出）**对驱**。这次没有造成损坏（W25Q64 的输出驱动能力弱、且 SPI 时钟下两者电平大部分时间一致），但这是一类**可能烧器件**的接线错误，不能靠运气。

---

## 根因

**把 W25Q64 的 `DO`/`DI` 接到了 STM32 的 `DI`/`DO`（同名相连），而不是交叉。** 属于典型的"器件命名与接线直觉冲突"：

- **UART 要交叉**（TX→RX、RX→TX）
- **SPI 不要交叉**（因为 STM32 侧用的是 **MISO/MOSI** 命名，而模块侧用的是 **DO/DI** 命名，两者是"功能名 vs 方向名"的差异）

即：

```
模块 DO (Data Out)  ──►  STM32 MISO (Master In)  = PA6
模块 DI (Data In)   ◄──  STM32 MOSI (Master Out) = PA7
```

用 `DO/DI` 对 `MISO/MOSI` 时，"接反"这个说法本身就有歧义 —— 所以**接线表里必须写清方向语义，而不只是写"别接反"**。

---

## 修复与验证

### 修复

`PA6 ↔ PA7` 两根线对调。

### 验证

```
[W25Q64] JEDEC ID = 0xEF4017
[W25Q64] 识别成功（Winbond，容量 8MB 量级）
```

LED 闪 3 次（与 OLED 的 1/2 次闪码区分开），历史记录功能随之正常。

### 防复发：把"症状 → 原因"写进固件的提示里

自检失败分支现在直接打印这条对应关系：

```c
UART_Puts("           若读回 0x000000 或 0xFFFFFF，多半是 DO/DI 接反了\r\n");
```

并在接线表里用**方向标注**替代"别接反"这种模糊说法：

| 模块引脚 | 方向 | 接到 |
|---|---|---|
| `DO` | Flash 输出 | `PA6`（MISO） |
| `DI` | Flash 输入 | `PA7`（MOSI） |

## 可迁移的教训

1. **总线读回的"异常值"本身是诊断数据**。全 0 / 全 1 / 随机值，各自指向不同的一类原因；先分类再动手，比盲目重接线快得多。
2. **交叉 / 不交叉取决于命名体系，不取决于直觉**。
   UART（TX/RX）要交叉，SPI 的 `DO/DI` ↔ `MISO/MOSI` 也要"交叉"，但 I2C 的 SCL/SDA 是同名相连 —— **三种总线三种规则，只能逐个记清**。
3. **把"症状 → 常见原因"写进错误提示**，是一次性投入、长期受益的事。这次花了 40 分钟，下次只要 1 分钟看日志。
4. **接反不只是"不工作"，也可能是"对驱"**。涉及两个输出脚相连的情形要格外小心，别把"没坏"当成"安全"。
