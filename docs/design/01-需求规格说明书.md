## 1. 引言

本文定义温湿度监测仪的功能需求、非功能需求与接口需求，作为设计、实现、测试和验收的共同依据。

### 1.2 术语与缩写

| 术语 | 含义 |
|---|---|
| 单总线（1-Wire） | 一根数据线分时收发的半双工协议，DHT11 使用 |
| 乒乓写入 | 用两个 Flash 扇区轮流写入，避免每次追加都要整扇区擦除 |
| 扇区（Sector） | W25Q64 的最小擦除单位，4 KB |
| 页面编程（Page Program） | W25Q64 的写入单位，一次最多 256 字节 |
| JEDEC ID | SPI Flash 的厂商+型号标识，W25Q64 为 `0xEF4017` |
| x10 定点 | 用整数表示一位小数，如 300 表示 30.0 °C |
| AP 模式 | WiFi 模块自建热点，不依赖外部路由器 |
| 降级 | 某个外设失败时，其余功能继续正常工作 |
| 画面 | OLED 上的一屏信息，共 5 个 |

## 2. 项目概述

### 2.1 背景与问题

市售温湿度计只能"看一眼当前读数"，无法回答四个实际问题：

| 问题 | 现有产品的不足 |
|---|---|
| 读数一直在跳，到底是多少 | 无滤波，末位数字反复变化 |
| 刚才一小时是不是一直这么热 | 无历史记录，过去的数据不可追溯 |
| 人不在现场，超限了也不知道 | 无本地报警、无远程通知 |
| 要凑到屏幕前才能看 | 无远程查看手段；云平台方案依赖外部网络 |

### 2.2 目标

用一块 STM32F103C8T6 最小系统板 + 常见模块，构建一个**不依赖云平台、不依赖路由器**的完整监测设备：采集 → 滤波 → 显示 → 存储 → 报警 → 无线推送全链路打通。

**部署场景**：宿舍、实验室、温室、小型机房 —— 这些场所通常没有现成的网络基础设施，也不可能为温湿度计单独布线。

### 2.3 用户与使用方式

| 用户 | 关注点 | 交互方式 |
|---|---|---|
| 现场值守人 | 当前读数是否超限 | 看 OLED 画面 0 / 听蜂鸣器 / 看 LED 闪速 |
| 需要趋势的人 | 过去一段时间的变化 | OLED 画面 3 翻页 / 画面 2 看极值 |
| 远程的人 | 不在现场也要知道 | 手机连热点，TCP 客户端收数据 |
| 开发者（本人） | 出问题时能定位 | 串口日志 + LED 故障闪码 |

### 2.4 版本范围

| 版本 | 目标 | 对应需求 |
|---|---|---|
| v1.0 | 采集链路打通：能读、能显示、能打印 | FR-01、FR-03、FR-11 |
| v1.1 | 具备实用价值：滤波、多画面、报警、计时 | FR-02、FR-04、FR-05、FR-07 |
| v1.2 | 完整功能：历史存储、极值、无线推送、自检 | FR-06、FR-08、FR-09、FR-10、FR-12、FR-13 |

## 3. 功能需求

优先级定义：**必须** = 缺失则项目不成立；**重要** = 显著影响实用性；**期望** = 提升体验。

### 3.1 采集与处理

#### FR-01 DHT11 温湿度采集（必须）

| 项 | 内容 |
|---|---|
| 描述 | 每隔固定周期读取一次 DHT11 的 40 位数据（5 字节），拼接成温度与湿度 |
| 接口 | 单总线，DATA 接 `PB0` |
| 细节要求 | ① 主机起始信号拉低 ≥ 18 ms<br>② 按"高电平时长"解码：延时 40 µs 后采样，高电平=1、低电平=0<br>③ **必须验证校验和**（前 4 字节之和取低 8 位），不匹配视为读取失败<br>④ 失败必须给出**可区分的错误编号**（无应答 / 读位超时 / 校验和错），不能只报"失败" |
| 验收准则 | 常温常湿下连续 100 次读取，成功率 ≥ 95%（DHT11 本身约 1 次/秒的采样率，本项目 2 秒一次留足余量）；校验和错误必须被捕获并计数 |

#### FR-02 滑动平均滤波（重要）

| 项 | 内容 |
|---|---|
| 描述 | 对最近 N 次**有效**采样做滑动平均，以滤波值作为显示、报警、存储、推送的统一数据源 |
| 参数 | 窗口 N = 5 |
| 细节要求 | ① 窗口未满时按**实际样本数**取平均，不能除以固定的 N<br>② 取整方向遵循 C 语言的"向零取整"，不得引入偏移<br>③ 滤波只接受有效样本（校验和错误的不入窗） |
| 验收准则 | 上电后第 1 个样本即输出该样本本身；输入 [300, 320, 280] 时输出 300（若错除以 5 会得到 180，属明显错误） |

#### FR-06 历史极值统计（期望）

| 项 | 内容 |
|---|---|
| 描述 | 记录上电以来温度/湿度的最大值与最小值，供"极值"画面显示 |
| 细节要求 | ① 用**滤波后**的值比较，避免单次跳变把极值带偏<br>② 上电初值应设计成"第一次采样必定刷新"，不额外引入"是否首次"标志<br>③ 极值**只增不减**（最大值不会回落），这是"历史极值"的定义 |
| 验收准则 | 上电后第一次采样完成，4 个极值即等于当前滤波值；此后用手捂热传感器，温度最大值上升且回落时不减小 |
| 备注 | 该需求在 v1.2 首次实现时存在缺陷：4 个变量只声明未赋值，极值画面恒显示 int16 极端值（3276.7 / −3276.8）。已于 2026-10-06 修复，并作为回归测试项 |

### 3.2 人机交互

#### FR-03 OLED 实时显示（必须）

| 项 | 内容 |
|---|---|
| 描述 | 128×64 OLED 显示温度、湿度、报警状态、采样统计 |
| 接口 | 软件 I2C，SCL=`PB6`、SDA=`PB7`，从机地址 `0x78` |
| 细节要求 | ① 所有数值以 x10 定点格式显示（`31.6C`），**不使用 `sprintf`**<br>② 屏幕可用行号只有 `0/2/4/6`（8×16 字库，每字符占 2 个 page）<br>③ 刷新不得阻塞采集与按键响应 |
| 验收准则 | 上电后 1 秒内显示就绪画面；温度数值随时间变化；全屏点亮自检为完整白色 |

#### FR-04 多画面切换（重要）

| 项 | 内容 |
|---|---|
| 描述 | 5 个画面（温湿度 / 时间 / 极值 / 历史 / WiFi）通过单按键循环切换 |
| 接口 | 按键 K1 接 `PB1`，内部上拉，按下为低电平 |
| 细节要求 | ① 短按切换到下一画面，到末尾回到第 0 个<br>② **消抖**：抖动不得被识别为多次按键<br>③ 只在"松开那一刻"上报一次，按住不放不得连续触发<br>④ 按键必须有可见反馈（LED 闪一下） |
| 验收准则 | 连续短按 5 次依次经过 5 个画面并回到第 0 个；按住 3 秒不松手，只产生一次动作 |

#### FR-05 运行时间显示（重要）

| 项 | 内容 |
|---|---|
| 描述 | 无 RTC 芯片，以开机时刻为 00:00:00，显示时:分:秒与运行总秒数 |
| 细节要求 | ① 时基必须来自**硬件定时器中断**，不得用软件延时累加<br>② 时间比较必须用**无符号减法**，以便自然处理 32 位计数溢出<br>③ 时间画面每秒自动刷新一次 |
| 验收准则 | 与手机秒表对比 10 分钟，偏差 ≤ 1 秒 |

#### FR-07 超阈值本地报警（重要）

| 项 | 内容 |
|---|---|
| 描述 | 温度 > 30.0 °C 或湿度 > 80.0 % 时，LED 转为快闪并驱动蜂鸣器 |
| 细节要求 | ① 判据用滤波后的值，避免单次跳变误报<br>② LED 频率必须能区分三种状态：正常 1 Hz / 报警 4 Hz / 采集失败 8 Hz<br>③ 蜂鸣器**断续鸣响**（响 200 ms、停 800 ms），不得长鸣<br>④ 阈值必须集中定义、便于修改 |
| 验收准则 | 手捂传感器使温度超过 30 °C，3 秒内 LED 转快闪、蜂鸣器断续响；松手回落后自动恢复 |

#### FR-12 上电自检与故障定位（重要）

| 项 | 内容 |
|---|---|
| 描述 | 上电依次自检各外设，并把**故障原因和排查方向**同时输出到 OLED 与串口；没接串口时用 LED 闪码表达结论 |
| 细节要求 | ① 自检顺序必须"从依赖最少的到依赖最多的"：先做不依赖任何外设的 LED 常亮，再做 I2C、SPI、记录系统、OLED<br>② 每个失败分支都要打印**具体查哪根线**，不得只说"失败"<br>③ 蜂鸣器上电短鸣 200 ms，用于快速判定触发极性是否配反<br>④ 串口输出 I2C 总线扫描结果（器件地址列表）<br>⑤ 仅在 OLED 初始化**失败**时才执行 SCL/SDA 接反判别（该动作会产生非法时序，不得在正常路径上运行） |
| 验收准则 | 故意拔掉 OLED：串口打印定位指引，LED 闪 1 次；故意让 W25Q64 的 DO/DI 接反：串口提示"若读回 0x000000 或 0xFFFFFF，多半是 DO/DI 接反了"，且其余功能正常 |

#### FR-13 外设独立降级（必须）

| 项 | 内容 |
|---|---|
| 描述 | 任一外设故障不得导致整机失效，其余功能必须继续工作 |
| 细节要求 | ① W25Q64 失败 → 温湿度采集/显示/串口/报警照常，"历史"画面显示 `Flash: FAIL`<br>② OLED 失败 → 数据仍从串口输出，采集与存储不中断<br>③ ESP-01S 失败 → 其余功能全部正常，"WiFi"画面显示 FAIL<br>④ 所有降级都必须有明确的串口提示说明后果 |
| 验收准则 | 逐个断开 W25Q64 / OLED / ESP-01S，其余功能均正常工作，串口有对应提示 |

### 3.3 数据持久化

#### FR-08 历史记录存储（重要）

| 项 | 内容 |
|---|---|
| 描述 | 每 1 分钟把当前滤波值写入 W25Q64，掉电不丢失 |
| 接口 | 硬件 SPI1：CS=`PA4`、CLK=`PA5`、DO/MISO=`PA6`、DI/MOSI=`PA7` |
| 细节要求 | ① 采用**双扇区乒乓**：每扇区 4 KB，头部 4 字节（魔数 `0xA5` + 状态 `0x01` + 起始序号 2 字节），其余 4092 字节按 3 字节/条存 1364 条<br>② 一条记录 = 温度 x10 两字节 + 湿度 x10 一字节（湿度限幅 0~255）<br>③ 每条记录带**自增序号**，读取时按序号还原时间顺序<br>④ 写入周期必须是分钟级而非采样级（Flash 擦写寿命有限：按 2 秒一条，一个扇区 45 分钟就写满）<br>⑤ 初始化时必须能**接着上次继续写**，不得清空已有记录<br>⑥ 掉电最多丢失当前这一条，历史整体不得损坏 |
| 验收准则 | 连续运行 > 5 分钟，历史画面能看到 ≥ 5 条记录；断电重启后记录数不减、内容不变、且继续追加 |
| 已知边界 | 序号为 uint16，约 65000 条（≈1090 小时）后回绕，会导致一轮排序颠倒。演示与短时运行不受影响；产品级需扩到 4 字节或初始化时归一化 |

#### FR-09 历史记录回看（重要）

| 项 | 内容 |
|---|---|
| 描述 | 在 OLED 历史画面分页查看记录，每页 3 条（1 行标题 + 3 行数据） |
| 细节要求 | ① 短按翻页，翻到最后一页回到第 1 页<br>② **必须提供长按返回主画面的通道** —— 该画面短按已被翻页占用，若无长按，用户将无法退出（单向门缺陷）<br>③ 进入该画面时直接定位到**最新一页**（用户关心"最近发生了什么"）<br>④ 只允许翻看最近 200 条，避免页号超出 uint8 范围<br>⑤ 新记录写入时若正停留在此画面，应自动跳到最后一页 |
| 验收准则 | 有 10 条以上记录时，翻页顺序正确、每页 4 行显示整齐；长按 1 秒能从该画面回到主画面 |

### 3.4 通信

#### FR-10 无线数据推送（重要）

| 项 | 内容 |
|---|---|
| 描述 | ESP-01S 自建 WiFi 热点 + TCP 服务器，手机连上后每 2 秒收到一行数据 |
| 接口 | USART2：`PA2`(TX)→模块 RXD、`PA3`(RX)←模块 TXD（交叉），`CH_PD` 必须接 3.3 V |
| 细节要求 | ① 配置顺序不可换：`ATE0` → `AT+CWMODE=2` → `AT+CWSAP` → `AT+CIPMUX=1` → `AT+CIPSERVER=1,8080`<br>② 发送采用三步握手：`AT+CIPSEND=0,<len>` → 等 `>` → 发正文字节 → 等 `SEND OK`，字节数必须与声明一致<br>③ 必须解析模块**主动上报**的 `0,CONNECT` / `0,CLOSED` 来跟踪客户端连接状态（该固件的 `AT+CIPSTATUS` 无法反映此信息）<br>④ 必须实现心跳（30 秒一次），无应答则重新初始化 —— 模块可能因供电跌落自行复位，而 STM32 毫无察觉<br>⑤ USART2 接收必须用中断而非轮询（115200 下字节间隔仅 87 µs，轮询周期 10 ms 会溢出丢字节）<br>⑥ 发送为阻塞操作，仅在有客户端连接时执行，避免空等超时<br>⑦ 数据帧格式须为纯文本键值对，任何 TCP 调试工具可直接阅读 |
| 验收准则 | 手机连热点 `ESP_TEMP`（密码 `12345678`），TCP Client 连 `192.168.4.1:8080`，稳定收到 `T=31.6C H=45.0% #106 A=1`，连续 200 帧无中断；拔掉热点后 30 秒内自动恢复 |
| 协议格式 | `T=<温度>C H=<湿度>% #<记录条数> A=<报警标志>\r\n` |

#### FR-11 串口调试日志（必须）

| 项 | 内容 |
|---|---|
| 描述 | USART1 @115200 输出完整运行日志 |
| 接口 | `PA9`(TX)、`PA10`(RX)，经 CH340 转 USB |
| 细节要求 | ① 每条采集日志包含：原始 5 字节 + 本次换算值 + 滤波值 + 报警状态<br>② 校验和失败时额外打印原始字节作为证据<br>③ 关键事件（按键、翻页、写记录、ESP 连接/断开）都要有时间可追溯的日志行<br>④ 日志输出不得使用 `sprintf`，须用自写定点格式化函数 |
| 验收准则 | 上电后串口能完整打印自检流程；运行期每 2 秒一行采集日志 |

## 4. 非功能需求

### 4.1 性能

| 编号 | 需求 | 指标 | 实测 |
|---|---|---|---|
| NFR-01 | 采样周期 | 2.0 s ± 10% | 符合 |
| NFR-02 | 按键响应延迟 | ≤ 50 ms | 约 10 ms（主循环按 10 ms 步进切片） |
| NFR-03 | 单帧推送时延 | ≤ 1 s | `>` 提示符 208~219 ms（12 次采样，抖动 11 ms） |
| NFR-04 | 历史记录查询 | 翻一页 ≤ 100 ms | 采用条数缓存，避免每次重扫 2728 条 |
| NFR-05 | 时钟精度 | 10 分钟偏差 ≤ 1 s | 内部 HSI，适合相对计时 |

### 4.2 资源约束

| 编号 | 约束 | 限值 | 实测 |
|---|---|---|---|
| NFR-06 | Flash 占用 | ≤ 64 KB | `text 18680` B = 18.2 KB（28.5%） |
| NFR-07 | RAM 占用 | ≤ 20 KB | `data 16` + `bss 1920` = 1.9 KB（9.5%） |
| NFR-08 | 不使用动态内存 | 全部静态分配 | 无 `malloc`，无 VLA |
| NFR-09 | 不使用浮点运算 | 全部定点 | 无 `float`/`double` |
| NFR-10 | 不使用 `sprintf` | 自写格式化 | `Util/fixed_str.c` |

> NFR-06~07 的余量是刻意保留的：后续加 RS485/Modbus 协议栈、参数双备份、IWDG 都需要空间。

### 4.3 可靠性

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-11 | 掉电数据完整性 | 掉电最多丢失当前一条记录，历史整体不损坏（双扇区乒乓保证） |
| NFR-12 | 外设故障隔离 | 见 FR-13，任一外设失败不扩散 |
| NFR-13 | 通信自恢复 | ESP 模块复位后 30 秒内自动重建热点与服务器 |
| NFR-14 | 缓存一致性自检 | 每写 100 条记录，用"实地重扫"核对一次增量计数，不一致则修正并报告 |
| NFR-15 | 中断安全 | 单总线时序期间关中断；清接收缓冲时关中断，避免与接收中断竞争计数器 |

### 4.4 可维护性

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-16 | 分层依赖单向 | `Core → Drivers → BSP → Util`，禁止反向 |
| NFR-17 | 寄存器隔离 | 所有寄存器读写只允许出现在 `BSP/` |
| NFR-18 | 接口收敛 | `BSP/Util/Drivers` 内部可变状态一律 `static`，跨模块只走 `.h` 中的访问函数 |
| NFR-19 | 约束自动强制 | 上述三条由脚本在每次编译前校验，违规即编译失败 |
| NFR-20 | 可配置项集中 | 阈值、窗口大小、SSID、端口等以宏定义在对应模块头文件中 |

## 5. 接口需求

### 5.1 硬件接口（引脚分配，唯一权威版本）

| 引脚 | 连接 | 配置 |
|---|---|---|
| `PA2` / `PA3` | ESP-01S RXD / TXD（USART2） | 复用推挽 / 浮空输入，**交叉接** |
| `PA4` | W25Q64 CS | 通用推挽（软件片选） |
| `PA5` | W25Q64 CLK | 复用推挽 |
| `PA6` | W25Q64 DO = MISO | 浮空输入 |
| `PA7` | W25Q64 DI = MOSI | 复用推挽 |
| `PB0` | DHT11 DATA | 开漏 + 内部上拉 |
| `PB1` | 按键 K1 | 上拉输入 |
| `PB5` | 蜂鸣器 IO | 推挽 2 MHz |
| `PB6` / `PB7` | OLED SCL / SDA | 开漏（软件 I2C） |
| `PA9` / `PA10` | USART1 TX / RX | 复用推挽 / 浮空输入 |
| `PA13` / `PA14` | SWDIO / SWCLK | 保留，不得占用 |
| `PC13` | 板载 LED | 推挽，**低电平点亮** |

**供电约束**：W25Q64 与 ESP-01S 只允许 3.3 V；STM32 板上的 5 V 引脚全程禁用。

### 5.2 人机接口

**LED 状态码**

| 现象 | 含义 |
|---|---|
| 长亮 1.5 s（上电） | 程序在运行，时钟与延时正常 |
| 闪 2 次（上电） | I2C SDA 自检通过 |
| 闪 1 次（上电） | I2C SDA 自检失败 |
| 闪 3 次（上电） | W25Q64 识别成功 |
| 1 Hz 慢闪 | 正常，未超限 |
| 4 Hz 快闪 | 报警 |
| 8 Hz 超快闪 | DHT11 读取失败 |
| 短按闪 1 次 | 按键已响应（短按） |
| 长按闪 2 次 | 按键已响应（长按） |

**按键操作**

| 操作 | 效果 |
|---|---|
| 短按 | 切换下一画面；在历史画面内为翻页 |
| 长按 ≥ 1 s | 直接回到画面 0（任何画面均有效） |

### 5.3 通信接口

| 接口 | 参数 |
|---|---|
| USART1（调试） | 115200-8-N-1，`BRR = fCK / 波特率`（不乘 16） |
| USART2（ESP-01S） | 115200-8-N-1，接收中断 + 192 字节缓冲 |
| SPI1（W25Q64） | 模式 0，软件片选 |
| 软件 I2C（OLED） | 从机地址 `0x78` |
| TCP 服务器 | `192.168.4.1:8080`，AP SSID `ESP_TEMP`，密码 `12345678` |

**无线数据帧**

```
T=31.6C H=45.0% #106 A=1\r\n
│        │        │     └─ 报警标志：1=超限，0=正常
│        │        └─────── Flash 中已存的历史记录条数
│        └──────────────── 滤波后湿度（%）
└───────────────────────── 滤波后温度（°C）
```

### 5.4 DHT11 失败错误码

| 错误码 | 含义 |
|---|---|
| 1 | 等不到 DHT11 拉低（无应答，多半是接线问题） |
| 2 | 等不到它把线放开 |
| 3 | 等不到应答高电平结束 |
| 4 | 读数据位时等不到高电平（时序被破坏） |
| 5 | 读数据位时等不到低电平 |
| 6 | 数据读全但校验和不匹配 |

## 6. 约束与假设

### 6.1 设计约束

| 编号 | 约束 | 原因 |
|---|---|---|
| C-01 | 不使用 HAL / 标准外设库，直接操作寄存器 | 项目定位是展示对底层外设的理解；同时省 Flash |
| C-02 | 不使用 `sprintf` / 浮点 | Flash 仅 64 KB，格式化引擎与软浮点代价过高 |
| C-03 | 不使用动态内存 | 嵌入式长期运行不容许碎片化；且便于静态分析 |
| C-04 | 不引入 RTOS | 任务数量少、时序简单，裸机主循环 + 中断足够；引入 RTOS 会增加栈占用与调试复杂度 |
| C-05 | 无外部晶振，使用内部 HSI | 不依赖晶振起振，提升上电可靠性；代价是精度约 ±1% |
| C-06 | 无 RTC 芯片 | 硬件成本与引脚占用；本项目只需要相对时间 |

### 6.2 假设

| 编号 | 假设 | 若不成立的影响 |
|---|---|---|
| A-01 | 用户按接线表正确接线并共地 | 表现为"外设无应答"，需依靠自检输出定位 |
| A-02 | DHT11 两次读取间隔 ≥ 1 s | 过密会导致读数漂移；本项目 2 s 一次 |
| A-03 | 供电能提供 ESP-01S 的 300 mA 峰值 | 供电不足会导致模块反复复位；已用 30 秒心跳自恢复兜底 |
| A-04 | 使用环境温度在 DHT11 量程内（0~50 °C） | 超量程读数无意义；负温已按规格书处理（最高位标记 + 取低 7 位取负） |
| A-05 | 单次连续运行时间 < 1000 小时 | 超过后 uint16 记录序号回绕（见 FR-08 已知边界） |
