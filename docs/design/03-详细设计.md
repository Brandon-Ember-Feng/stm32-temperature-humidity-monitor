## 1. BSP 层（板级支持包）

### 1.1 时钟树（`bsp_rcc.c`）

| 步骤 | 配置 | 结果 |
|---|---|---|
| 1 | 选 HSI 作为系统时钟源 | 8 MHz（内部 RC，无需外部晶振） |
| 2 | HSI 2 分频作 PLL 输入 | 4 MHz |
| 3 | PLL ×16 | 64 MHz 作为 SYSCLK |
| 4 | AHB 不分频 | HCLK = 64 MHz |
| 5 | APB1 2 分频 | PCLK1 = 32 MHz |
| 6 | APB2 不分频 | PCLK2 = 64 MHz |

**关键推论（容易漏）**：APB 预分频系数 ≠ 1 时，**挂在该总线上的定时器时钟 = PCLK × 2**。因此：

```
TIM2 计数时钟 = PCLK1 × 2 = 32 MHz × 2 = 64 MHz
```

这个 ×2 规则在 §1.2 里被再次用到。`BSP_CpuMhz()` 返回实际主频，供 `delay_us()` 与波特率计算动态使用 —— 万一时钟没升上去（仍是 HSI 8 MHz），公式依然能算出正确结果。

### 1.2 时间基准（`bsp_time.c`）

本项目用了**两个**时间外设，分工明确：

| 外设 | 用途 | 特征 |
|---|---|---|
| `SysTick` | `delay_us()` / `delay_ms()` 的"秒表" | 一次性：每次调用重新装载、用完即关 |
| `TIM2` | 系统时基 `BSP_Millis()` | 持续运行：每 1 ms 中断一次，从不被打扰 |

**为什么不能只用一个**：`SysTick` 被延时函数借走后会被反复重装和关闭，无法提供连续的"墙上时间"。而 DHT11 的位解码又必须在微秒级精确延时，两者需求冲突，所以分开。

**SysTick 延时实现**：

```c
void delay_us(uint32_t us)
{
    uint32_t reload = us * BSP_CpuMhz();          /* 1 µs = 64 个内核时钟 */
    if (reload > 0xFFFFFFU) reload = 0xFFFFFFU;   /* 24 位计数器上限 */
    SYSTICK_LOAD = reload - 1U;                   /* 计到 0 溢出 */
    SYSTICK_VAL  = 0;
    SYSTICK_CTRL = SYSTICK_CLKSOURCE | SYSTICK_ENABLE;
    while ((SYSTICK_CTRL & SYSTICK_COUNTFLAG) == 0U);   /* 轮询 COUNTFLAG */
    SYSTICK_CTRL = SYSTICK_CLKSOURCE;             /* 关闭计数 */
}
```

不用 `for` 空循环的原因：空循环的耗时受编译器优化等级影响，`-O1` 和 `-O2` 下差别很大；SysTick 由硬件计数，与程序在干什么无关。

**TIM2 时基实现**：

```c
TIM2_PSC = 63U;    /* 64 MHz / (63+1) = 1 MHz  → 1 个计数 = 1 µs */
TIM2_ARR = 999U;   /* 数满 1000 个计数溢出     → 每 1 ms 中断一次   */
```

```c
void TIM2_IRQHandler(void)
{
    TIM2_SR = 0U;          /* 清中断标志，否则会反复进中断 */
    g_ms_tick++;
}
```

**时间比较的写法约定**：一律用**无符号减法**，天然处理 32 位溢出：

```c
if ((BSP_Millis() - last_rec_ms) >= 60000U) { ... }   /* 正确 */
if (BSP_Millis() >= last_rec_ms + 60000U) { ... }      /* 错误：溢出瞬间会失效 */
```

`g_ms_tick` 声明为 `static volatile uint32_t`，只在中断里累加，对外只提供 `BSP_Millis()`。

### 1.3 GPIO 与 LED（`bsp_gpio.c`）

- 板载 LED 在 `PC13`，**低电平点亮**（板上有上拉），因此 `LED_On()` 写的是 `BSRR` 的复位位
- 按键 `PB1` 配置为上拉输入，按下读到低电平
- `PIN_SCL` = 6、`PIN_SDA` = 7（`PB6`/`PB7`）以宏定义存在，供接反判别复用

### 1.4 单总线物理层（`bsp_onewire.c`）

提供四个线级原语，**只做电平操作，不认识协议**：

| 函数 | 作用 |
|---|---|
| `OW_PinOut()` | `PB0` → 推挽输出（主机主动拉低） |
| `OW_PinIn()` | `PB0` → 上拉输入（松手，靠内部上拉拉高） |
| `OW_Read()` | 读 `PB0` 当前电平 |
| `OW_WaitLevel(want)` | 轮询等待电平变为 `want`，超时（`OW_TIMEOUT`）返回 0 |

**引脚模式必须来回切的原因**：STM32F1 的内部上拉只在**输入模式**下有效，输出模式下没有上拉。所以"松手"必须切回输入模式，线才能被上拉拉回高电平。

这个模块存在的意义就是架构约束的一个实例：`dht11.c` 里写的是"拉低 20 ms、等应答、读 40 位"，而"拉低需要写哪个寄存器"在这里 —— 换引脚只改这一个文件。

### 1.5 软件 I2C（`bsp_soft_i2c.c`）

- `PB6` = SCL，`PB7` = SDA，开漏输出
- 从机地址 `0x78`（= `0x3C << 1`，7 位地址 0x3C 左移一位）
- 额外提供三个**诊断专用**接口：

| 函数 | 用途 |
|---|---|
| `I2C_SdaEchoTest()` | 释放 SDA 后回读电平，直接回答"OLED 的线到底接上没有" |
| `I2C_BusIdleCheck(&scl, &sda)` | 读总线空闲电平（正常两者都应为 1） |
| `I2C_Scan(found, n)` | 全地址扫描，列出所有应答的器件地址 |
| `I2C_ProbePin(scl, sda, addr)` | 用**指定引脚映射**探测地址，用于判"两根线是否接反" |

> ⚠️ **`I2C_ProbePin` 只允许在 OLED 初始化失败分支里调用**。交换 SCL/SDA 映射会在两根线上产生"时钟/数据角色颠倒"的时序，从机看到的是非法波形，可能被卡在"传输中途等待"状态。正常启动路径上跑它会把本来好的器件搞坏。

**扫描器件数 ≥ 3 视为可疑**：真实 I2C 总线上不可能挂几十个器件，扫到一大堆说明 SDA 被拉死或悬空，读到的是假应答。

### 1.6 SPI1（`bsp_spi.c`）

- 模式 0（CPOL=0，CPHA=0），主模式，`PA4`~`PA7`
- `PA4` 是**软件片选**：通用推挽输出，由驱动手动拉低/拉高
- 核心原语 `SPI1_SwapByte(b)`：发一个字节同时收一个字节（SPI 是全双工）
- 速率与模式不匹配的症状很有辨识度：**读 JEDEC ID 得到 `0x000000` 或 `0xFFFFFF`**

### 1.7 USART1（调试口）与 USART2（ESP-01S）

**USART1**：115200-8-N-1，只发不收（本项目不解析上位机指令）。

波特率计算是踩过坑的地方：

```c
USART1_BRR = (BSP_CpuMhz() * 1000000U + BAUD / 2U) / BAUD;              /* APB2 = 主频 */
USART2_BRR = ((BSP_CpuMhz() * 1000000U / 2U) + BAUD / 2U) / BAUD;      /* APB1 = 主频/2 */
```

**`BRR = fCK / 波特率`，不要再乘 16。** 乘 16 的写法（`fCK/(16*baud)` 配 `DIV_Mantissa` 拆位）是另一种寄存器用法；直接给 BRR 赋值时，小数部分由低 4 位的分数域自动表达。乘错的症状是"串口全是乱码"。

**USART2 必须开接收中断**：

| 参数 | 值 | 说明 |
|---|---|---|
| 波特率 | 115200 | 一个字节 = 10 位 ≈ **87 µs** |
| 主循环轮询周期 | 10 ms | 比字节间隔慢 **115 倍** |
| 硬件接收寄存器容量 | **1 字节** | 第 2 个字节到来时前一个还没读走 → 置 ORE 标志并丢弃 |

结论：只靠轮询，模块回 `\r\nOK\r\n` 这 6 个字节里只有第 1 个 `\r` 能活下来，`OK` 永远凑不出来。

**中断服务程序**：

```c
void USART2_IRQHandler(void)
{
    if ((USART2_SR & (1U << 5)) != 0U)          /* RXNE=1 */
    {
        char c = (char)(USART2_DR & 0xFFU);     /* 读 SR 再读 DR，同时清 RXNE/ORE/NE/FE/PE */
        if (g_uart2_rx_n < (BSP_UART2_RX_BUF - 1U))
        {
            g_uart2_rx[g_uart2_rx_n] = c;
            g_uart2_rx_n++;
        }
        else
        {
            g_uart2_rx_n = 0U;                  /* 缓冲满：整体丢掉重来，比卡死好 */
            g_uart2_scan = 0U;
            g_uart2_rx[0] = c;
            g_uart2_rx_n  = 1U;
        }
        g_uart2_rx[g_uart2_rx_n] = '\0';        /* 始终保持 NUL 结尾 */
    }
}
```

缓冲大小 `BSP_UART2_RX_BUF = 192` 字节，够放一条完整回显。

**并发约定**：清缓冲（`BSP_Uart2_RxReset()`）必须**关中断**再清：

```c
__asm volatile ("cpsid i" ::: "memory");
BSP_Uart2_RxReset();
__asm volatile ("cpsie i" ::: "memory");
```

否则接收中断可能正好插在三行之间把新字节写进来，出现"计数被清零、字节却已写入"的错位。

**扫描游标机制**：`BSP_Uart2_ScanPos()` / `BSP_Uart2_ScanMove(pos)` 记录"哪些字节已经被关键词扫描处理过"，避免同一条 `CONNECT` 被反复判定。末尾留 6 个字节不扫，因为关键词可能正好被切在两批数据中间。

**`BSP_Uart2_RxPoll()` 的定位**：自接收中断启用后，它降级为"安全网" —— 万一某个字节在中断打开之前就进了 DR，或中断被长时间屏蔽过，这里还能补收。

## 2. Drivers 层（器件驱动）

### 2.1 DHT11（`dht11.c`）★

#### 2.1.1 协议时序

```
主机：     ┌────────────────────────┐
DATA: ─────┘  拉低 ≥18 ms（实配 20 ms）└─────────────────
                                                     释放（切输入+上拉）

DHT11：                              ┌──────┐          ┌────────────
DATA: ───────────────────────────────┘ 80µs └── 80µs ──┘  第 1 位开始
                                      低            高

每一位：    ┌─── 50 µs 低 ───┐┌── 高电平 ──┐
DATA:  ─────┘                └┘            └──────
                               ↑
                        延时 40 µs 后采样此点
                        高 → 数据 1（高电平 70 µs）
                        低 → 数据 0（高电平 26~28 µs）
```

#### 2.1.2 位解码算法（40 µs 判据的来历）

DHT11 用"高电平持续多久"编码，不是用"电平高低"：

| 数据 | 高电平时长 |
|---|---|
| 0 | 26 ~ 28 µs |
| 1 | 70 µs |

采样点选在 **40 µs**：

```
       28 µs          40 µs          70 µs
         │              │              │
    ─────┘              ▼              └─────
    采样点落在这里，距 0 的上界余 12 µs，距 1 的下界余 30 µs
```

两边余量都 ≥ 12 µs，非常稳。代码实现：

```c
for (i = 0U; i < 5U; i++) {
    dat[i] = 0U;
    for (j = 0U; j < 8U; j++) {
        if (!OW_WaitLevel(1U)) { g_dht_err = 4U; return 0U; }   /* 等 50 µs 低结束 */
        delay_us(40U);                                          /* 关键判据 */
        dat[i] <<= 1;                                           /* 高位在前 */
        if (OW_Read() != 0U) dat[i] |= 1U;
        if (!OW_WaitLevel(0U)) { g_dht_err = 5U; return 0U; }    /* 等高电平结束 */
    }
}
```

#### 2.1.3 必须关中断的原因

`delay_us(40)` 之后立刻采样。如果这 40 µs 内来了 TIM2 中断（每 1 ms 一次），ISR 执行要花几个微秒，采样点被推迟 —— 极端情况会把 1 读成 0。

```c
uint8_t DHT11_Read(void)
{
    Irq_Disable();                  /* cpsid i */
    r = DHT11_ReadRaw();
    Irq_Enable();                   /* cpsie i  */
    ...
}
```

**代价**：一次读取约 24 ms，时基少计约 24 ms，占 2 秒周期的 1.2%。对"显示运行时间"用途可接受；对精确计时不可接受。

#### 2.1.4 错误码设计

失败必须可区分，否则排查只能靠猜：

| 码 | 含义 | 排查方向 |
|---|---|---|
| 1 | 等不到 DHT11 拉低 | 传感器没供电 / DATA 线断 / 引脚错 |
| 2 | 等不到它放开 | 上拉缺失（本项目已开内部上拉） |
| 3 | 等不到应答高电平结束 | 时序被干扰 |
| 4 | 读位时等不到高电平 | 时序被破坏（中断未关净？） |
| 5 | 读位时等不到低电平 | 同上 |
| 6 | 校验和不匹配 | 数据不可信；此时仍把原始 5 字节留下当证据 |

注意 `g_dht_err = 6` 时**原始字节照样复制到 `g_dht_raw`** —— 串口会打印它们，是定位"是哪个字节出了问题"的直接证据。

#### 2.1.5 计数器归属（约束 3 的实例）

```c
uint8_t DHT11_Read(void)
{
    ...
    /* 【接口收口】计数器归驱动自己维护。
     * 原来这两个 ++ 写在 Core/main.c 里 —— 上层去改驱动内部统计，
     * 属于典型的分层穿越，而且漏一次调用计数就永久失真。 */
    if (r != 0U) { g_dht_ok_cnt++; }
    else         { g_dht_fail_cnt++; }
    return r;
}
```

### 2.2 DHT11 帧解析（`dht11_frame.c`）★ 纯逻辑

从驱动里剥离出的三个纯函数，输入只有 5 字节数组，输出是整数，**不 include 任何 `bsp_*.h`**：

```c
#define DHT_FRAME_LEN 5U
uint8_t DHT_CheckSum(const uint8_t raw[DHT_FRAME_LEN]);
int16_t DHT_DecodeTemp(const uint8_t raw[DHT_FRAME_LEN]);
int16_t DHT_DecodeHumi(const uint8_t raw[DHT_FRAME_LEN]);
```

| 函数 | 规则 |
|---|---|
| `DHT_CheckSum` | `(raw[0]+raw[1]+raw[2]+raw[3]) & 0xFF == raw[4]` → 返回 1 |
| `DHT_DecodeHumi` | `raw[0] * 10 + raw[1]`（湿度无负值） |
| `DHT_DecodeTemp` | `raw[2]` 最高位 = 1 表示负温：取低 7 位 `* 10 + raw[3]` 后**取负** |

**负温不是补码**：DHT11 规格书用"最高位做符号标记，低 7 位是数值"，不是二进制补码。这是很容易写错的地方，因此单测里专门有一条 `test_frame_negative_one_degree`。

```c
int16_t DHT_DecodeTemp(const uint8_t raw[DHT_FRAME_LEN])
{
    int16_t t;
    if ((raw[2] & 0x80U) != 0U)
        t = (int16_t)(-((int16_t)(raw[2] & 0x7FU) * 10 + (int16_t)raw[3]));
    else
        t = (int16_t)((int16_t)raw[2] * 10 + (int16_t)raw[3]);
    return t;
}
```

**已知边界**：全零帧 `{0,0,0,0,0}` 的校验和是 `0 == 0`，数学上合法 —— 单测里作为"边界存在"记录，而不是当作 bug。

### 2.3 W25Q64（`w25q64.c`）

#### 2.3.1 指令集（本项目用到的 6 条）

| 指令 | 码 | 用途 |
|---|---|---|
| Write Enable | `0x06` | 擦/写之前**必须先发**，置位 WEL |
| Read Status Register 1 | `0x05` | 查 BUSY 位（bit0） |
| Read Data | `0x03` | 发完 24 位地址后连续吐数据 |
| Page Program | `0x02` | 页编程，**一页 256 字节** |
| Sector Erase | `0x20` | 扇区擦除 4 KB |
| JEDEC ID | `0x9F` | 厂商 + 类型 + 容量 |

#### 2.3.2 两条必须遵守的物理规则

1. **Flash 只能把 1 写成 0，不能把 0 写回 1**。擦除（整扇区变 `0xFF`）是唯一把 0 变 1 的手段，且最小单位是 4 KB。
2. **Page Program 不能跨页**：地址落在页内何处，一次最多写到该页末尾。

第 2 条的处理：

```c
while (len > 0U) {
    uint32_t room = 256U - (addr & 0xFFU);        /* 本页还剩多少字节 */
    uint32_t n    = (len < room) ? len : room;    /* 本次能写多少 */
    W25_WriteEnable();
    /* 发 0x02 + 24 位地址 + n 字节 */
    ...
    addr += n;  buf += n;  len -= n;
    if (!W25_WaitBusy()) break;
}
```

#### 2.3.3 页编程的写使能顺序

```
W25_WriteEnable()        → 0x06，置 WEL
W25_WaitBusy()           → 轮询 0x05，等 BUSY=0
发 0x02 + 地址 + 数据    → 数据在 CS 拉高时真正写入
W25_WaitBusy()           → 等写入完成（页编程约 0.7 ms，扇区擦除约 45 ms）
```

`W25_SectorErase(addr)` 内部做 `addr &= 0xFFFFF000U`，因为**扇区擦除只认高 12 位**：给 `0x1234` 和给 `0x1000` 擦的是同一个扇区。

### 2.4 历史记录存储（`hist_store.c` + `hist_index.c`）★★ 本项目核心

#### 2.4.1 为什么不能简单在末尾追加

Flash 一个扇区只有 4 KB，写满后必须擦除才能继续写；但擦除是"整扇区"动作，一擦就把该扇区已有记录全毁了。若只有 1 个扇区，就必须"读出全部 → 擦除 → 写回"，而且中途掉电就全丢。

#### 2.4.2 双扇区乒乓布局

```
扇区 A @ 0x000000                 扇区 B @ 0x001000
┌──────────────────────┐          ┌──────────────────────┐
│ [0] 魔数 0xA5        │          │ [0] 魔数 0xA5        │   ← 4 字节扇区头
│ [1] 状态 0x01(有效)  │          │ [1] 状态 0x01        │
│ [2..3] 起始序号(大端)│          │ [2..3] 起始序号      │
├──────────────────────┤          ├──────────────────────┤
│ 记录 0: 3 字节       │          │ 记录 0: 3 字节       │
│ 记录 1: 3 字节       │          │ 记录 1: 3 字节       │
│ ...                  │          │ ...                  │
│ 记录 1363（最后一条）│          │ 记录 1363            │
└──────────────────────┘          └──────────────────────┘
     4092 B 数据区 / 3 B = 1364 条/扇区
     总容量 2728 条 ≈ 45.5 小时（1 条/分钟）
```

**一条记录（3 字节）**：

| 字节 | 内容 |
|---|---|
| `[0]` | 温度 ×10 高字节 |
| `[1]` | 温度 ×10 低字节 |
| `[2]` | 湿度 ×10，**限幅到 0~255** |

温度用两字节补码，可表达 −3276.8 ~ +3276.7 °C；湿度限幅是因为 DHT11 量程 0~100 %（×10 后 0~1000）超出单字节，但实际湿度不会超过 100 %，限幅到 255 表示 25.5 % 以上就饱和 —— 这是**已知的设计取舍**：牺牲高湿区间精度换取每记录 1 字节空间。

> 观察：湿度 >25.5 % 时记录值饱和在 255。若将来需要精确记录，应把记录扩到 4 字节。本项目的历史画面显示"趋势"，该取舍可接受。

#### 2.4.3 写入状态机（`W25_RecAppend`）

```
入口：检查 g_rec_ok
  │
  ├─ g_wr_count >= 1364（当前扇区写满）？
  │     ├─ 是：next = 当前扇区的对家（乒乓）
  │     │      W25_SectorErase(对家)             ← 擦掉旧数据
  │     │      写新扇区头，序号 = g_wr_seq（接上，不重头）
  │     │      同步更新缓存：g_recX.seq / g_cntX = 0
  │     │      g_wr_sector = next; g_wr_count = 0
  │     └─ 否：继续用当前扇区
  │
  ├─ 组装 3 字节 → 写到 sector + 4 + g_wr_count * 3
  │
  └─ g_wr_count++; g_wr_seq++; 增量更新 g_cntX 与 g_rec_total
```

**任何时刻总有一个扇区是"完整的旧数据"，另一个在接新数据** —— 掉电最多丢失当前这一条，历史不会整体崩掉。

#### 2.4.4 初始化决策（`W25_RecInit`）

读两个扇区的头，按四种组合决定从哪继续写：

| 扇区 A | 扇区 B | 决策 |
|---|---|---|
| 空 | 空 | **格式化 A**：擦 A，写头（魔数 + 状态 + 序号 0），从 A 开始 |
| 有数据 | 空 | 接着写 A：`g_wr_count = realA`，`g_wr_seq = recA.seq + realA` |
| 空 | 有数据 | 接着写 B（同理） |
| 有数据 | 有数据 | 选**序号更大**的那个作为写入区（序号大 = 那一轮更晚开始 = 数据更新）；若它也满了，留给下一次 `Append` 触发乒乓 |

**判定"扇区有效"**：`hdr[0] == 0xA5 && hdr[1] == 0x01`，否则视为从未写过或无效。无效扇区即使里面恰好有残留数据也按 0 条计。

**精确计数**（`W25_CountSector`）：逐条读，**连续读到 3 个 `0xFF` 视为末尾**。为什么可以用 `0xFF` 当"空位"标志？因为擦除后 Flash 全是 `0xFF`，而一条真实记录不可能是 `0xFFFF`（温度 = 3276.7 °C，物理上不存在）。

> **性能提示**：这个函数要逐条读 1364 次，约 19 ms。只在"初始化"和"写完一条"时调用，结果缓存到 `g_cntA/g_cntB`，**绝不在读历史画面时每行调一次** —— 那样翻一页要 150 ms。

#### 2.4.5 读取寻址（`hist_index.c`）★ 纯逻辑

乒乓切换后两个扇区的**物理顺序**与**逻辑时间顺序**不再一致，所以要按序号还原：

```
逻辑序号 0 ────────────────► 逻辑序号 total-1
   │                                │
   └─ 旧扇区（序号小的）             └─ 新扇区（序号大的）
      └─ 序号大的那段数据更早写，反而排在前面
```

```c
uint8_t Hist_Locate(const Hist_Index_T *ix, uint32_t idx, uint32_t *addr)
{
    uint32_t total = ix->cnt_a + ix->cnt_b;
    if (idx >= total) return 0U;                       /* 越界 */

    if ((ix->cnt_a > 0U) && (ix->cnt_b > 0U)) {
        uint8_t  a_is_newer = (ix->seq_a >= ix->seq_b) ? 1U : 0U;
        uint16_t old_cnt    = a_is_newer ? ix->cnt_b : ix->cnt_a;
        uint32_t old_sec    = a_is_newer ? W25_SECTOR_B : W25_SECTOR_A;

        if (idx < (uint32_t)old_cnt) {
            *addr = old_sec + W25_REC_HDR_SIZE + idx * W25_REC_SIZE;      /* 旧扇区 */
        } else {
            uint32_t k       = idx - (uint32_t)old_cnt;
            uint32_t new_sec = a_is_newer ? W25_SECTOR_A : W25_SECTOR_B;
            *addr = new_sec + W25_REC_HDR_SIZE + k * W25_REC_SIZE;        /* 新扇区 */
        }
    } else {
        uint32_t sec = (ix->cnt_a > 0U) ? W25_SECTOR_A : W25_SECTOR_B;     /* 只有一个扇区有数据 */
        *addr = sec + W25_REC_HDR_SIZE + idx * W25_REC_SIZE;
    }
    return 1U;
}
```

调用侧只负责把驱动内部状态**快照**成入参：

```c
Hist_Index_T ix;
ix.cnt_a = g_cntA;  ix.cnt_b = g_cntB;
ix.seq_a = g_recA.seq;  ix.seq_b = g_recB.seq;
if (Hist_Locate(&ix, idx, &addr) == 0U) return 0U;
W25_Read(addr, raw, W25_REC_SIZE);
```

**已知边界：序号回绕**。序号存在 2 字节里（uint16），每扇区 1364 条，写满约 48 次乒乓（约 65000 条 ≈ 1090 小时）后序号绕回 0，那一刻 `seq_a >= seq_b` 会误判新旧，导致排序颠倒一轮。演示与短时运行不受影响；产品级应把序号扩到 4 字节，或在 init 时归一化（把两个 seq 都减去较小值）。

#### 2.4.6 缓存一致性自检

正常写入走"增量 +1"，不重新扫扇区。每写 `W25_VERIFY_EVERY = 100` 条，做一次实地对账：

```c
if ((Hist_Count() % W25_VERIFY_EVERY) == 0U) {
    uint32_t inc_total = Hist_Count();
    W25_RefreshCounts();                  /* 实地重扫两个扇区，约 40 ms */
    if (Hist_Count() == inc_total)
        UART_Puts("[记录] 自检通过：增量计数与实地扫描一致\r\n");
    else
        UART_Puts("[记录] 自检不一致！（以实地为准，已修正缓存）\r\n");
}
```

代价约 40 ms / 100 分钟，可以忽略；收益是**开发期能尽早发现寻址或乒乓逻辑的问题** —— 这比等到"历史画面数据错乱"再回头查要便宜得多。

### 2.5 ESP-01S AT 驱动（`esp8266_at.c`）★★

#### 2.5.1 实测参数（脱机测出来的，不是抄文档）

| 项 | 实测值 |
|---|---|
| AT 版本 | 1.1.0.0（May 11 2016） |
| SDK | 1.5.4 |
| 出厂波特率 | 115200 |
| `AT+CWSAP` | 用 **4 个参数** |
| 无客户端时 `CIPSEND` | 回 `link is not valid` |
| `>` 提示符耗时 | **208 ~ 219 ms**（12 次采样，抖动仅 11 ms） |
| 关回显 | `ATE0` 后应答最干净 |

`ESP_PROMPT_MS` 设为 1000 ms，是实测值的 **4.5 倍余量**。提示符按时到达时这个上限根本消耗不到，给宽无害；重连后第一次发送或模块繁忙时可能更慢。

#### 2.5.2 初始化序列（顺序不可换）

```
ATE0                    关回显（最多重试 3 次，每次间隔 200 ms）
   ↓  先切 AP 模式
AT+CWMODE=2             AP 模式
   ↓  才能建热点
AT+CWSAP="ESP_TEMP","12345678",5,3    （信道 5，加密等级 3）
   ↓  AP 模式下必须开多连接
AT+CIPMUX=1
   ↓  最后开 TCP 服务器
AT+CIPSERVER=1,8080
   ↓
AT+CIPCLOSE=0           清掉可能残留的 0 号链路（只看不断言）
AT+CIFSR                回读 IP 当证据（失败不算错误）
   ↓
g_esp_ready = 1
```

**为什么要 `AT+CIPCLOSE=0`**：如果模块在 STM32 上电前就已建过连接、而那条连接被对端粗暴掐断（RST），模块内部会留下"僵尸链路" —— 此后所有 `AT+CIPSEND=0` 都回 `link is not valid`，而 `AT+CIPSTATUS` 照样报 `STATUS:5` 看着像连着。2026-09-21 实测踩到过。

**为什么要 `AT+CIFSR`**：老固件对查询指令支持不全，失败不算错误，只当参考 —— 成功时回显里有 `+CIFSR:APIP,"192.168.4.1"`，是"热点真的起来了"的直接证据。

**初始化整体重试一次**：

```c
uint8_t ESP_Init(void)
{
    BSP_Uart2_Init();
    delay_ms(500U);              /* 等模块上电稳定：它上电会先吐一串启动信息 */
    if (ESP_Setup()) return 1U;
    UART_Puts("[ESP] 第一轮配置失败，隔 300ms 重试一次\r\n");
    delay_ms(300U);
    if (ESP_Setup()) return 1U;
    g_esp_ready = 0U;
    return 0U;
}
```

> `delay_ms(500)` 不能省：模块上电会先吐一串启动信息，此时发 AT 会被这串信息干扰，也容易撞上它还没准备好的窗口。

#### 2.5.3 发送三步握手

```
① → AT+CIPSEND=0,<len>       声明"我要发 len 字节"
② ← '>'                      必须等到它，才能发内容
③ → <len 字节正文>           长度必须和声明的一模一样
④ ← SEND OK                  确认发送成功
```

**这中间不能插别的指令**，所以整段是阻塞的（有超时兜底），约 300 ms。

```c
/* 组装数据帧：T=29.3C H=50.0% #12 A=0 */
n = StrAppendStr(pay, n, "T=");
n = StrAppendFix1(pay, n, temp_x10);
n = StrAppendStr(pay, n, "C H=");
n = StrAppendFix1(pay, n, humi_x10);
n = StrAppendStr(pay, n, "% #");
n = StrAppendU32(pay, n, seq);
n = StrAppendStr(pay, n, " A=");
n = StrAppendU32(pay, n, (uint32_t)alarm);
n = StrAppendStr(pay, n, "\r\n");
len = (uint32_t)n;
```

用"键=值"的紧凑文本，手机端随便一个网络调试助手就能读，不需要解析库；每帧以 `\r\n` 结尾，一条一行，肉眼和脚本都好处理。

**失败时的补判逻辑**（重要）：

```c
if (!ESP_WaitFor(">", ESP_PROMPT_MS)) {
    g_esp_fail++;
    /* 模块没上报 CLOSED、但已经发不出去了 —— 靠这句错误文本补判 */
    if (ESP_Has("link is not valid")) {
        g_esp_link = 0U;
        UART_Puts("[ESP] 客户端其实已断开（link is not valid）\r\n");
    }
    return 0U;
}
```

这解决了"连着但已经发不出去"的粘滞状态：模块没上报 `CLOSED`，但实际链路已断。清掉 `g_esp_link` 后，主循环下一轮就不再来打扰，避免每 2 秒白等 1 秒超时。

#### 2.5.4 客户端连接状态跟踪（`ESP_TrackLink`）

老固件的 `AT+CIPSTATUS` 只回 `STATUS:5`，看不出"有没有客户端连着"。想知道客户端上下线，只能靠模块**主动**吐出来的两条消息 —— 这是本方案里唯一的事件驱动部分。

```c
static void ESP_TrackLink(void)
{
    if (BSP_Uart2_RxLen() < 7U) return;
    /* 末尾 6 个字节留到下一轮再扫：关键词可能正好被切在两批数据中间 */
    limit = (uint16_t)(BSP_Uart2_RxLen() - 6U);

    for (i = BSP_Uart2_ScanPos(); i < limit; i++) {
        if (ESP_MatchAt(i, "CONNECT")) {
            BSP_Uart2_ScanMove(i + 7U);          /* 游标跳过这条，避免重复判定 */
            if (g_esp_link == 0U) { g_esp_link = 1U; ... }
        } else if (ESP_MatchAt(i, "CLOSED")) {
            BSP_Uart2_ScanMove(i + 6U);
            if (g_esp_link != 0U) { g_esp_link = 0U; ... }
        }
    }
    if (BSP_Uart2_ScanPos() < limit) BSP_Uart2_ScanMove(limit);
}
```

#### 2.5.5 心跳与自动恢复（`ESP_KeepAlive`）

**为什么必须做**：ESP-01S 峰值电流 300 mA+，供电一瞬跌（比如手机刚连上、发射突然变强）就可能自己复位。复位后**热点和 TCP 服务器全部丢失，但 STM32 这边毫无察觉** —— 代码看起来一切正常，用户那边却是"怎么突然连不上了"。

```
每 30 秒（ESP_KA_MS）：
  ├─ 发 AT，等 OK（500 ms 超时）
  │    ├─ 不通 → 认为模块复位：g_esp_ready = 0; g_esp_link = 0
  │    │         等 500 ms → 重跑 ESP_Setup() → 成功则报"已恢复"，失败则留给下一个 30 秒
  │    └─ 通   → 若当前无客户端，打印"心跳正常，等待手机连接"
  └─
```

`ESP_RxService()` 把收数据与心跳打包，供主循环每 10 ms 调用一次，**全程非阻塞**：

```c
void ESP_RxService(void)
{
    if (g_esp_ready == 0U) return;
    BSP_Uart2_RxPoll();
    ESP_TrackLink();
    ESP_KeepAlive();
}
```

### 2.6 AT 应答匹配（`esp_parse.c`）★ 纯逻辑

```c
uint8_t ESP_MatchAtIn(const char *buf, uint16_t len, uint16_t pos, const char *token);
uint8_t ESP_FindToken(const char *buf, uint16_t len, const char *token);
```

**接口设计的实质改进**：原 `ESP_Has` 依赖缓冲区末尾的 `'\0'` 来界定搜索范围。但 USART2 是定长缓冲、可能刚好被填满而没有结束符。新接口把长度显式传入，并用 `if (k >= len) return 0U;` 保证不越界：

```c
/* ESP_MatchAtIn 的核心：每比较一个字符都先确认没越过 len */
while (token[k] != '\0') {
    if (k >= len) return 0U;                    /* 越界保护 */
    if (buf[pos + k] != token[k]) return 0U;
    k++;
}
```

`ESP_FindToken` 对空串约定返回 1（空 token 处处匹配）。

**适配层让调用点一行未改**：

```c
static uint8_t ESP_MatchAt(uint16_t pos, const char *t)
{ return ESP_MatchAtIn(BSP_Uart2_RxBuf(), BSP_Uart2_RxLen(), pos, t); }

static uint8_t ESP_Has(const char *t)
{ return ESP_FindToken(BSP_Uart2_RxBuf(), BSP_Uart2_RxLen(), t); }
```

### 2.7 按键（`key.c`）

#### 2.7.1 三个必须处理的细节

| # | 细节 | 不处理的后果 |
|---|---|---|
| ① | **消抖**：机械触点在闭合/断开瞬间有 5~10 ms 抖动 | 按一次被识别成好几次，画面连跳几格 |
| ② | **检测"按下沿"而不是"按下状态"** | 一直按住会连续触发 |
| ③ | **区分短按 / 长按** | 历史画面短按是翻页，若只有短按，用户进去就出不来 |

#### 2.7.2 状态机（为什么在"松手那一刻"才上报）

```
状态：last = 1（松开）

  now == 0 且 last == 1（1→0 下降沿：刚按下）
      └─ delay_ms(15) 等抖动过去
           └─ 再确认一次仍是 0？
                ├─ 是：last = 0; t_press = BSP_Millis()
                └─ 否：抖动，忽略
      return 0            ← 按下这一刻先不报，等松手再定性

  now == 1 且 last == 0（0→1：刚松手）
      └─ last = 1
      return (BSP_Millis() - t_press >= 1000) ? 2 : 1     ← 这时才知道按了多久

  其他情况：return 0      ← 一直按住时 last 保持 0，不会重复上报
```

**如果按下就先报一次短按、按住 1 秒后再报一次长按**，同一个动作会触发两次：用户会看到"先翻了一页、又突然跳回主画面"。

### 2.8 OLED 显示（`ssd1306.c` + `font8x16.c` + `ui_pages.c`）★

#### 2.8.1 屏幕结构与被踩过的坑

SSD1306 是 128×64，纵向 64 像素被切成 **8 个 page**（每 page 8 像素）。字库是 8×16 点阵，一个字符要占「上半 page + 下半 page」两格：

```
page 0  ┌─────────────┐  ┐
page 1  │  第 1 行字符 │  ┘  ← 一个 8×16 字符占 2 个 page
page 2  ┌─────────────┐  ┐
page 3  │  第 2 行字符 │  ┘
page 4  ┌─────────────┐  ┐
page 5  │  第 3 行字符 │  ┘
page 6  ┌─────────────┐  ┐
page 7  │  第 4 行字符 │  ┘
        └─────────────┘
```

**⇒ 整屏实际只有 4 行字符位置：`page 0 / 2 / 4 / 6`。**

`OLED_ShowChar` 里有一道保护：

```c
if (page > 6U || col > 120U) return;
```

**传 `page = 7` 会整行一个字都不画，而且是静默失败**（没有错误提示）。这是本项目踩过的最耗时的坑之一。

#### 2.8.2 历史画面的排版（`HIST_PER_PAGE = 3` 的来历）

```c
#define HIST_PER_PAGE   3U    /* 每页 3 条（+1 行标题 = 4 行占满） */
#define HIST_ROW_TOP    2U    /* 第 1 条数据画在第 2 行，即 page 2   */
...
uint8_t rpag = (uint8_t)(HIST_ROW_TOP + row * 2U);   /* row = 0,1,2 → page 2,4,6 */
```

**曾经写成 4 条的后果**（数据行从 page 1 起排，即 1/3/5/7）：
1. 第 1 条覆盖标题下半截
2. 每条上下错开 8 像素、互相重叠
3. 第 4 条落在 page 7，被 `page > 6U` 保护拦掉，整行一个字都不画

**⇒ 整页糊成一团。** 所以每页 3 条是"4 行 − 1 行标题"算出来的，不是随便定的。

#### 2.8.3 为什么只允许翻看最近 200 条

```c
#define HIST_MAX 200U
```

两个原因：
1. `g_hist_page` 是 `uint8_t`。全部 2728 条 = 910 页 > 255，页号会回绕
2. 用户想看的就是"最近发生了什么"。200 条 = 67 页，刚好

越界处理：

```c
show_cnt = (Hist_Count() > HIST_MAX) ? HIST_MAX : Hist_Count();
first    = Hist_Count() - show_cnt;        /* 起点后推，只保留最新的那些 */
```

#### 2.8.4 防残影：为什么要 `StrPadTo`

```c
n = StrPadTo(line, n, 16U);   /* 用空格补到 16 字符宽 */
OLED_ShowStr(0, 0, line);
```

同一行的新旧内容长度不一样时（例如 `T=29.5C` → `T=9.5C`），短的那一次会把上一次多出来的字符留在屏幕上。所有行统一补到 16 字符宽即可消除。OLED 每行正好 16 个 8×16 字符（128 / 8 = 16）。

#### 2.8.5 五个画面

| 画面 | `g_mode` | 内容行（page 0 / 2 / 4 / 6） |
|---|---|---|
| 温湿度 | 0 | `Temp` / `Humi` / `Status`（ALARM 或 Normal）/ `OK:45 F:0 M1/5` |
| 时间 | 1 | `Time 时:分:秒` / `Uptime 秒数` / — / 页脚 |
| 极值 | 2 | `Tmax` / `Tmin` / `Hmax` / `Hmin` |
| 历史 | 3 | 1 行标题 + 3 条记录（`#序号 T=.. H=..`） |
| WiFi | 4 | `WiFi OK/FAIL` / `SSID` / `IP:192.168.4.1` / `Cli:1 TX:106` |

时间画面**每秒单独重绘一次**（只画 2 行，很快），让秒位跳动；其他画面在每次采样后重绘。

### 2.9 蜂鸣器（`beep.c`）

- 3 针模块（VCC / IO / GND），`IO` 接 `PB5`，模块**自带三极管驱动级**，IO 只认逻辑电平，不消耗引脚电流
- 本项目模块丝印标「低电触发」⇒ `BEEP_ACTIVE_HIGH = 0`（IO=0 响，IO=1 静音）
- **有源**蜂鸣器给电就响，不需要 PWM 方波；**无源**蜂鸣器必须用方波驱动 —— 换模块时要注意
- `BEEP_TRIG_TXT` / `BEEP_TRIG_STR` 把当前极性配置输出到串口和 OLED，便于"一直长鸣"时快速判断是极性配反

**上电短鸣 200 ms 自检的意义**：极性对不对这件事，如果等温度升到 30 °C 触发报警才知道，可能要等半小时。短鸣一下，5 秒内就能定案：

| 现象 | 结论 |
|---|---|
| 短鸣后安静 | 极性与接线都正确 |
| 一直长鸣 | 极性反了，把 `BEEP_ACTIVE_HIGH` 取反重烧 |
| 完全没声 | 查 VCC/GND 是否接反、是否量到 3.3 V |

## 3. Util 层（纯算法）

### 3.1 滑动平均滤波（`filter.c`）★

```c
void Filter_Init(Filter_T *f) {
    for (i = 0; i < FILTER_N; i++) f->buf[i] = 0;
    f->idx = 0U;  f->cnt = 0U;
}

void Filter_Push(Filter_T *f, int16_t v) {
    f->buf[f->idx] = v;                       /* 写满一圈就从 0 覆盖 */
    f->idx++;
    if (f->idx >= FILTER_N) f->idx = 0U;      /* 环形缓冲 */
    if (f->cnt < FILTER_N) f->cnt++;
}

int16_t Filter_Avg(const Filter_T *f) {
    int32_t sum = 0;
    if (f->cnt == 0U) return 0;
    for (i = 0U; i < f->cnt; i++) sum += (int32_t)f->buf[i];
    return (int16_t)(sum / (int32_t)f->cnt);  /* ★ 除以实际个数，不是 FILTER_N */
}
```

**两个容易写错的点**：

| 点 | 正确 | 错误的后果 |
|---|---|---|
| 窗口未满时 | 除以 **`f->cnt`**（实际个数） | 除以 `FILTER_N` 会得到偏小的值：上电后推入 300/320/280，正确均值 300，错除 5 得 180 |
| 取整方向 | C 语言整数除法**向零取整**（`-3/2 = -1`） | 若改成向下取整，负温会系统性偏小 1 |

求和用 `int32_t` 累加，避免 `int16_t` 溢出（5 × 32767 = 163835 超出 16 位）。

### 3.2 定点格式化（`fixed_str.c`）

统一用"返回新末尾下标"的风格，便于连续调用：

```c
uint8_t n = 0U;
n = StrAppendStr(line, n, "Temp: ");
n = StrAppendFix1(line, n, g_temp_avg);
n = StrPadTo(line, n, 16U);
OLED_ShowStr(0, 0, line);
```

| 函数 | 作用 | 关键实现 |
|---|---|---|
| `StrAppendStr` | 追加字符串 | 逐字符拷贝，末尾补 `'\0'` |
| `StrAppendU32` | 追加无符号整数 | 先取余倒序存入 `tmp[11]`，再倒着取出来变正序 |
| `StrAppendFix1` | 追加一位小数（`-105` → `"-10.5"`） | 负数先输出 `'-'` 并取绝对值；整数部分 `/10`，小数部分 `%10` |
| `StrPadTo` | 补空格到指定宽度 | 防残影（见 §2.8.4） |
| `StrAppendPad2` | 两位数字补零（`9:5:3` → `"09:05:03"`） | `v > 99` 时钳到 99 |

**为什么不用 `sprintf`**：标准库会把一大坨格式化代码和浮点支持链接进来，Flash 只有 64 KB，能省就省。自己写几行反而更快更小 —— 但代价是**格式改了要改代码**，所以这个文件必须有单元测试覆盖。

## 4. Core 层（应用逻辑）

### 4.1 数据模型（`app.c` / `app.h`）

```c
static Filter_T s_temp_filt, s_humi_filt;     /* 滤波器实例（static，不出模块） */

int16_t  g_temp_now, g_humi_now;              /* 本次原始读数（×10） */
int16_t  g_temp_avg, g_humi_avg;              /* ★ 显示/存储/推送的统一数据源 */
uint8_t  g_alarm;

int16_t  g_temp_min = 32767, g_temp_max = -32768;   /* 极值初值 = int16 两端 */
int16_t  g_humi_min = 32767, g_humi_max = -32768;
```

**极值初值的设计**：故意设成 `int16_t` 的两个极端值，第一次采样必定刷新它们，**不需要额外的"是否第一次"标志位**。这是一处典型的"用数据设计代替控制逻辑"。

```c
void DHT_Process(void)
{
    for (i = 0U; i < DHT_FRAME_LEN; i++) raw[i] = DHT_RawByte(i);
    g_temp_now = DHT_DecodeTemp(raw);
    g_humi_now = DHT_DecodeHumi(raw);

    Filter_Push(&s_temp_filt, g_temp_now);
    Filter_Push(&s_humi_filt, g_humi_now);
    g_temp_avg = Filter_Avg(&s_temp_filt);
    g_humi_avg = Filter_Avg(&s_humi_filt);

    /* 用滤波后的值来比，免得单次跳变把极值带偏 */
    if (g_temp_avg > g_temp_max) g_temp_max = g_temp_avg;
    if (g_temp_avg < g_temp_min) g_temp_min = g_temp_avg;
    if (g_humi_avg > g_humi_max) g_humi_max = g_humi_avg;
    if (g_humi_avg < g_humi_min) g_humi_min = g_humi_avg;

    /* 用滤波后的值判断报警，避免单次跳变引起误报 */
    g_alarm = ((g_temp_avg > TEMP_ALARM_X10) || (g_humi_avg > HUMI_ALARM_X10)) ? 1U : 0U;
}
```

**关于 `app.h` 里这几个 `extern` 的说明**（原文照录）：

> 应用层为单实例单线程（主循环 + 中断只写时基），无并发访问，故直接以 `extern` 暴露。
> 若将来引入 RTOS，应改为访问器 + 互斥保护。

这是**有意为之的例外**：约束 3 只查 `BSP/Util/Drivers`，`Core/` 作为顶层不查。但例外被写清楚了，且写明了补救方向。

**极值缺陷的修复记录**（保留在代码注释里，作为回归项）：

> 【2026-10-06 修复】原 v1.2 只声明了这 4 个变量、从未赋值，导致「极值画面」恒显示 `int16_t` 的两个极端值（3276.7 / −3276.8）。

### 4.2 主循环调度（`main.c`）★

#### 4.2.1 设计动机

原来"每 2 秒采集一次"是用 `delay_ms(2000)` 死等的。后果是**按键按下去最多要等 2 秒才有反应，手感很差**。

改造：把 2 秒切成 **200 个 10 ms 的小步**，每步顺手做几件事。按键响应延迟降到约 10 ms。

#### 4.2.2 结构

```
while (1)
{
    ┌─ 一次采集（每 2 秒进入一轮）──────────────────────────────┐
    │  DHT11_Read()                                          │
    │    ├─ 成功：DHT_Process() → DHT_PrintUart()             │
    │    │        → OLED_Refresh()                            │
    │    │        → blink_ms = 报警 ? 125 : 500               │
    │    └─ 失败：打印 err（校验和错时附原始 5 字节）           │
    │             → blink_ms = 62（8 Hz 超快闪）              │
    └────────────────────────────────────────────────────────┘
    ┌─ 历史记录（每 60 秒）────────────────────────────────────┐
    │  if (Hist_IsReady() && (BSP_Millis() - last_rec_ms) >= 60000U)   │
    │      W25_RecAppend(g_temp_avg, g_humi_avg)              │
    │      每 100 条 → W25_RefreshCounts() 实地对账            │
    │      若正在看历史画面 → 自动跳到最后一页                  │
    └────────────────────────────────────────────────────────┘
    ┌─ 无线推送（有客户端时）──────────────────────────────────┐
    │  if (ESP_IsReady() && ESP_IsLinked())                   │
    │      ESP_SendFrame(g_temp_avg, g_humi_avg, Hist_Count(), g_alarm) │
    │      若正在看 WiFi 画面 → 刷新（能看到 TX 计数在涨）      │
    └────────────────────────────────────────────────────────┘
    ┌─ 内层 200 × 10 ms 切片 ──────────────────────────────────┐
    │  for (step = 0; step < 200; step++)                     │
    │  {                                                      │
    │      delay_ms(10);                                      │
    │      toggled += 10;                                     │
    │      ESP_RxService();          ← 收上报 + 30 s 心跳（非阻塞）│
    │      if (toggled >= blink_ms) { LED_Toggle(); toggled = 0; }│
    │      if (g_alarm) {                                     │
    │          if (BSP_Millis() % 1000 < 200) BEEP_On();       │
    │          else                           BEEP_Off();      │
    │      } else BEEP_Off();                                 │
    │      if (g_mode == 1 && sec != last_sec) OLED_PageTime();│
    │      Key_Scan() → 短按切画面/翻页、长按回画面 0            │
    │  }                                                      │
    └────────────────────────────────────────────────────────┘
}
```

#### 4.2.3 蜂鸣器节拍的实现技巧

```c
if ((BSP_Millis() % 1000U) < 200U) BEEP_On();
else                               BEEP_Off();
```

借 `BSP_Millis()` 的 200 ms 相位来判断，**不需要额外的状态变量**。效果是响 200 ms、停 800 ms。

为什么不让它一直响：一是吵，二是"断续"这个动作本身就在传递信息 —— 光看灯要盯着，听声音不用看就知道出事了。

#### 4.2.4 为什么历史记录定 60 秒

| 理由 | 数据 |
|---|---|
| Flash 擦写寿命（W25Q64 约 10 万次/扇区） | 按 2 秒一条，1364 条一个扇区 **45 分钟就写满**；按 60 秒一条，一个扇区能撑 **22 小时以上** |
| "历史趋势"本来就该是分钟级的 | 2 秒级的抖动没有记录价值 |

#### 4.2.5 按键处理的两条分支

```
Key_Scan() 返回 2（长按）
    → g_mode = 0; g_hist_page = 0
    → OLED_Refresh()
    → LED 双闪（60/80/60 ms）反馈

Key_Scan() 返回 1（短按）
    → g_mode == 3（历史画面）？
    │     ├─ 是：翻页
    │     │     pages = ceil(min(Hist_Count, HIST_MAX) / HIST_PER_PAGE)
    │     │     g_hist_page++; if (g_hist_page >= pages) g_hist_page = 0
    │     │     OLED_PageHistory()
    │     └─ 否：切下一个画面
    │           g_mode++; if (g_mode >= MODE_NUM) g_mode = 0
    │           若刚进入历史画面 → 直接跳到最后一页（最新数据最有用）
    │           OLED_Refresh()
    → LED 单闪（30 ms）反馈
```

**长按是必需项，不是锦上添花**（代码注释原文）：

> 历史画面上短按被用来翻页了，如果按键只有短按一种动作，用户一旦按进历史画面就再也退不出来，只能按复位键 —— 等于把这个功能做成了单向门。长按就是那道逃生门，在任何画面都有效。

**为什么页数按 `HIST_MAX` 算而不是按 `Hist_Count()`**：否则页号会超出 `uint8_t` 范围（2728 条 = 910 页）。

**LED 反馈的设计理由**：长按给"双闪"、短按给"单闪"，用户**不用盯着屏幕**也能确认自己那一下算短按还是长按。

### 4.3 上电自检顺序（`main.c`）

顺序原则：**从依赖最少的到依赖最多的**。这样一旦前面就失败，能立刻定位到"问题不在外设"。

| 步 | 动作 | 失败含义 / 输出 |
|---|---|---|
| 1~7 | `Clock_Init` → `SysTick_Init` → `TIM2_Init` → `UART_Init` → `GPIO_Init` → `SPI1_Init` → `Buzzer_Init` | 时钟与引脚基础 |
| 8 | **LED 长亮 1.5 s**（不碰任何外设） | 连它都不亮 ⇒ 问题在烧录或供电，与外设无关 |
| 8.5 | **蜂鸣器短鸣 200 ms** | 极性判定的快速通道（见 §2.9） |
| 9 | `I2C_SdaEchoTest()` → LED 闪 2 次（通过）/ 1 次（失败） | 直接回答"OLED 的线到底接上没有" |
| 10 | `I2C_BusIdleCheck()` + `I2C_Scan()` | 打印空闲电平与器件地址列表；器件 ≥ 3 个则报"可疑" |
| 11 | `W25_Probe()` 读 JEDEC ID → 成功闪 3 次 | 同时验证 SPI1 四根线接线与模式配置；失败时打印逐脚对照表 |
| 12 | `W25_RecInit()` | 打印已有条数与继续写入的扇区 |
| 12.5 | **I2C 复核扫描**（进入 OLED 初始化前再扫一次） | 两次都扫到 `0x78` ⇒ 器件全程在线；第一次有、这次没了 ⇒ 中间某一步把总线搞挂了 |
| 13 | `OLED_Init()` + 全屏点亮 1 s | 成功时若 SDA 自检没过，提醒"这个'成功'可能是假应答" |
| 13.5 | `ESP_Init()`（阻塞 1~2 秒） | 放在主循环之前一次做完，失败不影响主功能 |

**LED 闪码的编码设计**：2 次 = I2C 通过、1 次 = I2C 失败、3 次 = Flash 识别成功。次数互不相同且都是小数字，**没接串口时靠数闪灯就能判断**。

**全屏点亮 1 秒的意义**：如果这一屏是完整的白色，说明 128×64 共 8192 个像素全部受控，通信与显存都没问题。若全黑而地址又能应答，问题就在屏幕侧（面板排线松动 / 其实是 SH1106 芯片 / 模块损坏）。

**"复核扫描"为什么有用**：它把"OLED 不亮"这个笼统问题切成两种截然不同的原因 —— 器件掉线（硬件/接触）还是初始化序列有问题（软件）。这一步只用几十毫秒，却能把排查范围砍掉一半。

### 4.4 外设独立降级矩阵

| 失效外设 | 仍可用的功能 | 失效的功能 | 用户看到的提示 |
|---|---|---|---|
| W25Q64 | 采集、显示、串口、报警、无线推送 | 历史记录、极值画面仍可看（极值不依赖 Flash） | 串口打印"识别失败 + 逐脚对照"；OLED 显示 `Flash: FAIL`；历史画面显示 `Check SPI wire: CS4 CLK5 DO6 DI7` |
| OLED | 采集、串口、存储、报警、无线推送 | 本地显示 | 串口打印"没有 OLED 也能继续采集，数据会从串口输出" |
| ESP-01S | 全部本地功能 | 无线推送 | 串口打印"WiFi 不可用，其余功能不受影响" + 查线指引；WiFi 画面显示 FAIL |
| DHT11 | 显示框架、按键、Flash 记录系统 | 温湿度数据 | LED 8 Hz 超快闪；串口打印 err 编号与原始字节 |
| 蜂鸣器 | 其他全部 | 声音报警（LED 仍在报警） | 上电短鸣自检时就能发现 |

## 5. 关键流程时序

### 5.1 一次完整采集（含阻塞点）

```
t=0ms      DHT11_Read() 开始
           ├─ Irq_Disable()                    ← 关中断
           ├─ 拉低 PB0，delay_ms(20)
           ├─ 释放，等应答（80+80 µs）
           ├─ 读 40 位（每位约 50+40 µs）        ≈ 4 ms
           └─ Irq_Enable()                     ← 开中断
           总耗时约 24 ms（时基少计 24 ms，占 2 s 周期的 1.2%）
t=24ms     DHT_Process()                       <1 ms
t=25ms     DHT_PrintUart()                     约 8 ms（115200 下约 90 字符）
t=33ms     OLED_Refresh() → OLED_PageData()     约 5 ms（仅重绘 2 行）
t=38ms     ESP_SendFrame()（有客户端时）
           ├─ AT+CIPSEND → 等 '>'               208~219 ms
           ├─ 发正文 → 等 SEND OK               约 60~80 ms
           └─ 合计约 300 ms
t=338ms    进入 200 × 10 ms 切片循环
           ├─ 每 10 ms：ESP_RxService()（非阻塞）
           ├─ 每 blink_ms（125/500/62 ms）：LED_Toggle()
           ├─ 报警时按 200/800 ms 相位驱动蜂鸣器
           └─ 每步都扫按键 ⇒ 按键延迟 ≈ 10 ms
t=2338ms   下一轮
```

### 5.2 双扇区乒乓的一次翻转

```
初始：A 已写 1364 条（满），B 存有一轮更早的数据（假设 B 的序号更小）
      逻辑顺序：[ B 的全部 ] → [ A 的全部 ]

第 1365 条到来：
   g_wr_count(=1364) >= W25_REC_PER_SECTOR
   ├─ next = 1（B）
   ├─ W25_SectorErase(B)                    ← B 的旧数据被擦掉（约 45 ms）
   ├─ 写 B 的新头：魔数 0xA5 / 状态 0x01 / 序号 = g_wr_seq
   ├─ g_recB.seq = g_wr_seq; g_cntB = 0
   ├─ g_rec_total = g_cntA + g_cntB
   └─ g_wr_sector = 1; g_wr_count = 0

   写入 B 的第 0 条

翻转后逻辑顺序：[ A 的全部 ] → [ B 的新记录 ]
        （A 的序号更小 ⇒ A 是"旧扇区"，排在逻辑序号前面）
```

**掉电安全性**：擦除 B 期间掉电，A 仍完整，`W25_RecInit` 下次会读到"A 有效、B 无效"⇒ 接着写 A（或按 A 满则重新乒乓）。**任何单点掉电都不会让历史整体失效**。

### 5.3 ESP 断线自动恢复

```
正常运行：每 10 ms ESP_RxService()，每 2 s 推一帧

供电跌落导致模块自行复位：
   ├─ 模块内部：热点与 TCP 服务器全部丢失（但 STM32 不知道）
   ├─ 手机侧：连接断开
   └─ STM32 侧：g_esp_ready 仍为 1 → 继续尝试推送 → 全部超时

30 秒后心跳到期：
   ├─ 发 AT，500 ms 内无 OK
   ├─ 打印"[ESP] 模块无应答（很可能复位了），重新初始化..."
   ├─ g_esp_ready = 0; g_esp_link = 0
   ├─ delay_ms(500)
   └─ ESP_Setup() → 成功：打印"[ESP] 已恢复：热点重新建立"
                    失败：打印"[ESP] 恢复失败，30 秒后再试"

恢复后：手机需重新连热点并建 TCP Client（模块复位后旧连接已不存在）
```

## 6. 错误处理约定

| 约定 | 实现 |
|---|---|
| 失败必须可区分 | DHT11 用 1~6 错误码；ESP 区分"等不到 `>`"与"等不到 SEND OK" |
| 失败必须留证据 | 校验和错时保留原始 5 字节；ESP 用 `ESP_LogResp()` 把回显打成一行（换行替换为空格） |
| 失败必须说清"查哪里" | 自检失败分支打印具体引脚对照（如 `CS->PA4 CLK->PA5 DO->PA6(MISO) DI->PA7(MOSI)`） |
| 失败不能扩散 | 见 §4.4 降级矩阵 |
| 所有阻塞都要有超时 | `OW_WAIT_LEVEL` 用 `OW_TIMEOUT`；`W25_WaitBusy` 用计数器上限；AT 等待用 `ESP_PROMPT_MS` / `ESP_SENDOK_MS` |
| 越界访问必须拦在函数内 | `DHT_RawByte(idx)` 越界返回 0；`Hist_Locate` 越界返回 0；`OLED_ShowChar` 越界直接 return |
